How XML Elements Become JSON Keys

XML is a tree of elements. Each element has a tag name and can contain child elements, text content, and attributes. JSON is a tree of key/value pairs. The converter walks the XML tree and produces a matching JSON tree, following a few simple rules.

A simple element with only text content becomes a string or number value: 

<age>30</age>    →    "age": 30

An element with child elements becomes a nested object: 

<person>
  <name>Alice</name>
  <age>30</age>
</person>

    →

"person": {
  "name": "Alice",
  "age": 30
}

The tag name becomes the JSON key, and the element's content becomes the value. Nesting is preserved at every level, so a five-level XML tree produces a five-level JSON tree.

Attributes — Stored Under _attributes

XML attributes are stored inside the opening tag, like id="123". JSON has no equivalent concept, so the converter groups all of an element's attributes into a special object called _attributes. That object sits alongside the element's other keys. 

<person id="123" role="admin">
  <name>Alice</name>
</person>

    →

"person": {
  "_attributes": {
    "id": 123,
    "role": "admin"
  },
  "name": "Alice"
}

The underscore prefix is a convention that makes attributes easy to identify and avoids collisions with real child elements. If an element has both an attribute called name and a child element called name, the attribute is inside _attributes.name and the child element is at name — no conflict.

Repeated Elements Become Arrays

XML allows multiple sibling elements with the same tag name. For example, a book catalog might have many <book> elements. In JSON, a key can only appear once in an object, so the converter groups repeated siblings into an array. 

<catalog>
  <book>A</book>
  <book>B</book>
  <book>C</book>
</catalog>

    →

"catalog": {
  "book": ["A", "B", "C"]
}

The rule is simple: if a tag appears once, its value is the single object. If it appears more than once, its value becomes an array of those objects. This is the standard convention used by xml2js and most other XML-to-JSON tools.

Note that the converter does not force every element into an array. A single <book> produces a single object, not a one-element array. This keeps the output compact and matches how most JSON APIs are structured.

Text Content and Mixed Content

If an element has only text content and no children or attributes, the text becomes the value directly. If the text is numeric, it is converted to a number. If it is true or false, it becomes a boolean.

Elements with a mix of text and child elements — called mixed content — are the hardest case. XML allows text to be interspersed with child elements in any order. The converter uses the _ key to hold the text content when child elements also exist. For example: 

<p>Hello <b>world</b>!</p>

    →

"p": {
  "_": "Hello !",
  "b": "world"
}

Mixed content is rare in data-oriented XML but common in documents. If your XML is document-style (HTML-like), expect to see _ keys in the output.

A Real Example: XML In, JSON Out

Here is a complete example showing how the converter handles a small, realistic document with attributes, nested children, and repeated elements.

Input XML

<?xml version="1.0"?>
<company name="Acme">
  <employee id="1">
    <name>Alice</name>
    <role>Engineer</role>
    <active>true</active>
  </employee>
  <employee id="2">
    <name>Bob</name>
    <role>Designer</role>
    <active>false</active>
  </employee>
</company>

Output JSON

{
  "company": {
    "_attributes": {
      "name": "Acme"
    },
    "employee": [
      {
        "_attributes": { "id": 1 },
        "name": "Alice",
        "role": "Engineer",
        "active": true
      },
      {
        "_attributes": { "id": 2 },
        "name": "Bob",
        "role": "Designer",
        "active": false
      }
    ]
  }
}

Notice four things: the root element <company> became the top-level key company; its attribute name is inside _attributes; the two <employee> siblings became an array; and the numeric id attribute and boolean active values were typed as number and boolean rather than as strings.

Malformed XML — What Happens

XML is strict. Unlike HTML, it does not tolerate unclosed tags, mismatched tags, or unescaped special characters. The parser will refuse to process malformed XML, and you will see an error message. Some common problems and their fixes:

  • Unclosed tag — <name>Alice without a closing </name>. Add the closing tag.
  • Mismatched tag — <name>Alice</nme>. The closing tag must match the opening tag exactly, including case.
  • Unescaped & — <p>A & B</p> is invalid. Use &amp; instead.
  • Unescaped < — text containing < must use &lt;.
  • Multiple root elements — <a/><b/> at the top level. XML must have exactly one root element. Wrap them in a container.
  • Invalid attribute syntax — <a id=1> without quotes around the value. Attribute values must be quoted.

Unlike some lenient parsers, this tool does not attempt to repair malformed XML. Guessing at the intended structure can silently produce wrong data, so the parser stops and reports the error. Fix the XML and try again.

CDATA, Comments, and Processing Instructions

CDATA sections (<![CDATA[...]]>) are used to include text that would otherwise need escaping. The parser treats them as ordinary text, so the content of a CDATA block appears as a plain string in the JSON.

Comments (<!-- ... -->) are stripped during parsing. They do not appear in the JSON output at all, because JSON has no comment syntax.

Processing instructions and the XML declaration (<?xml ... ?>) are also stripped. They are metadata about the document, not data.

Namespaces

XML namespaces, declared with xmlns: attributes, are preserved. An element like <xs:element> appears in the JSON as a key called xs:element. The namespace declarations themselves appear as attributes under _attributes with the literal key xmlns:xs. This preserves the information without imposing any namespace resolution logic.

Practical Uses

Migrating a legacy API response: Copy the XML response and convert it to JSON for use in a modern JavaScript application.

Reading a configuration file: Convert XML config files to JSON for easier editing or for feeding into a JSON-based tool.

Inspecting SOAP responses: SOAP APIs return XML. Convert the response to JSON to see the structure clearly.

Feeding XML data into a JavaScript pipeline: JSON is native to JavaScript, so converting XML first avoids the need for an XML parser in the target application.

XML to JSON Questions

Is my data safe?

Yes. All parsing happens locally in your browser using xml2js. Your XML is never uploaded to any server. You can disconnect from the internet after the page loads and the tool will continue to work.

How are XML attributes handled?

Attributes are grouped into a special _attributes object that sits alongside the element's other keys. For example, <person id="123"> becomes {"person": {"_attributes": {"id": 123}}}. The underscore prefix avoids collisions with real child elements.

How are repeated elements handled?

When the same tag appears more than once as a sibling, its values are collected into a JSON array. A single occurrence produces a single object, not a one-element array. This matches the convention used by xml2js and most other XML-to-JSON tools.

Are numbers and booleans converted?

Yes. Text that looks like a number is stored as a JSON number, and true or false is stored as a JSON boolean. Other text stays as a string.

What happens with mixed content (text + child elements)?

When an element contains both text and child elements, the text is stored under a key called _, and the child elements are stored as normal keys. For example, <p>Hello <b>world</b>!</p> becomes {"p": {"_": "Hello !", "b": "world"}}.

What happens if my XML is malformed?

The parser will refuse to process it and show an error message. Common causes are unclosed tags, mismatched tags, unescaped & or <, multiple root elements, and unquoted attribute values. Fix the XML and try again. The tool does not attempt to repair malformed XML.

Are CDATA sections preserved?

Yes. The content of a CDATA block is treated as ordinary text and appears as a plain string in the JSON output. CDATA delimiters themselves are stripped.

Are comments preserved?

No. Comments are stripped during parsing because JSON has no comment syntax. If you need to preserve comments, use a different format or store them as separate data.

Are XML namespaces supported?

Yes. Prefixed tag names like <xs:element> appear as keys with the prefix intact, for example "xs:element". Namespace declarations appear as attributes under _attributes. The tool does not resolve namespaces to URIs.

Can I convert a SOAP response?

Yes. Copy the raw XML from the SOAP envelope and paste it into the input. The converter will produce JSON with the same structure. Namespaces and attributes are preserved.

Can I convert JSON back to XML?

This tool only converts one direction: XML to JSON. For the reverse, use a JSON-to-XML tool or write a small script. The round trip is not always lossless because of the _attributes and _ conventions.

What is the maximum file size?

About 10 MB. Beyond that, browser memory and rendering speed become limiting factors. For very large XML files, split them into smaller chunks and convert each one.
