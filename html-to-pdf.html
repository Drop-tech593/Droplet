How HTML to PDF Conversion Works

The converter renders your HTML in a hidden iframe, applies a print stylesheet with the page size, orientation, and margins you choose, then rasterises the result into a PDF using html2pdf. This is a print-style conversion, not a browser screenshot — it takes the HTML and CSS as they would appear on paper.

The whole process runs in your browser. Your HTML is read into memory, rendered, and written as a PDF. Nothing is uploaded.

HTML and CSS Support

The converter supports the same HTML and CSS that your browser does. In practice, this means:

  • Elements: headings, paragraphs, lists, tables, images, links, blockquotes, horizontal rules, semantic tags (header, section, article, footer), and most others.
  • Inline CSS: works fully. Styles in a <style> block in the <head> also work.
  • Fonts: system fonts (Arial, Georgia, Times, Courier) work everywhere. Web fonts loaded from a CDN work if the CDN is reachable and allows cross-origin loading.
  • Colours and backgrounds: solid colours, gradients, borders, and border-radius all render. Background images may or may not load depending on their source.
  • Flexbox and Grid: modern layout modes are supported by the underlying browser engine and render correctly.

Print Styling and @media print

The converter respects @media print rules in your CSS. If your HTML includes a print stylesheet, those rules will apply in the PDF. This is the recommended way to control exactly how the document looks on paper — for example hiding navigation, expanding link URLs, or forcing page breaks.

If you do not provide print rules, the screen styles are used as-is. This usually looks fine for simple documents. For complex layouts with sidebars, navigation, or interactive elements, add a print stylesheet to hide or restyle those parts.

One useful pattern: hide UI elements with @media print { .no-print { display: none } }, and force page breaks with page-break-before: always or page-break-after: always on specific elements.

External Resources and CORS

HTML often references external resources: stylesheets, images, fonts, and scripts. Whether those resources load depends on where they are hosted and how they are configured.

  • Same-origin resources generally load. If you paste HTML that references files on your own machine or on a server that allows same-origin access, they will work.
  • Cross-origin resources with CORS headers load successfully. Many CDNs (Google Fonts, jsDelivr, unpkg, Cloudflare) send the right headers, so stylesheets and fonts from those sources usually work.
  • Cross-origin resources without CORS headers are blocked by the browser. The PDF will render without those assets — a missing image, an unstyled block, and so on.
  • Resources on the local file system referenced by relative paths may not resolve when the HTML is rendered in an iframe. Use absolute URLs or inline the content.

The safest approach is to inline everything you can. Put CSS in a <style> block, embed images as data URLs, and avoid remote dependencies where possible. This guarantees the PDF will render exactly as you see it in the preview.

JavaScript Limitations

JavaScript is not executed during PDF conversion. The iframe is sandboxed without allow-scripts, so any <script> tags in your HTML are ignored. This is a deliberate security measure: running arbitrary scripts from a file you paste would be unsafe.

The practical effect is that pages relying on JavaScript to render their content — single page applications, client-side rendered frameworks (React, Vue, Angular), or pages that build the DOM on load — will produce a PDF containing only the static HTML that was present at load time. If the visible content is generated by JavaScript, it will be missing from the PDF.

To work around this, save the fully rendered page from your browser (for example using "Save Page As" → "Webpage, Complete") and upload the saved HTML, or paste the rendered HTML directly from the browser's developer tools.

Page Sizing, Orientation, and Margins

Four page sizes are offered:

  • A4 — 210 × 297 mm, standard in most of the world.
  • Letter — 8.5 × 11 in, standard in the United States and Canada.
  • Legal — 8.5 × 14 in, used for US legal documents.
  • A3 — 297 × 420 mm, twice the area of A4, useful for posters and wide tables.
  • A5 — 148 × 210 mm, half of A4, useful for booklets and small handouts.

Orientation can be portrait or landscape. Landscape is useful for wide tables and diagrams. Margins range from none (0 mm) to wide (20 mm). The default is 10 mm, which leaves a modest border around the content.

Pages break automatically as content flows. You can force breaks with CSS using page-break-before: always, page-break-after: always, or page-break-inside: avoid on elements that should not be split.

Quality and File Size

The quality setting controls the JPEG compression of the rasterised page images. Standard (0.7) produces the smallest files and is fine for on-screen reading. High (0.85) is the default and works well for most documents. Maximum (0.95) is best for printing or when the document contains fine detail.

Because the PDF is built from rasterised page images, the file size depends mostly on the page count and quality, not on the complexity of the HTML. A 10-page document at Maximum quality can easily be several megabytes.

What Is Not Preserved

  • Interactivity. Clickable links render as styled text but are not clickable in the PDF. Form fields, buttons, and other interactive elements are rasterised.
  • Animations and transitions. CSS animations, transitions, and hover states are captured at their initial state only.
  • Selectable text. The PDF pages are rasterised images, so text cannot be selected or searched. If you need selectable text, use a PDF library that writes real text runs, or export the document from a word processor.
  • Video and audio. Media elements are not rendered.
  • Canvas and SVG drawing. Static SVG usually renders; canvas elements render only if the canvas has already been drawn to before conversion.

Practical Examples

Saving an invoice template: Paste the invoice HTML, choose A4, Portrait, Normal margins, High quality. The result is a print-ready invoice PDF.

Archiving a documentation page: Save the page from your browser, upload the HTML file, choose A4, Portrait, and High quality. Add a print stylesheet to hide the navigation and sidebar.

Producing a wide table report: Choose A3, Landscape, and Narrow margins. The wide table fits on one page instead of being split awkwardly.

Creating a booklet: Choose A5, Portrait, and Wide margins. Two A5 pages fit on one A4 sheet when printed double-sided, ready for saddle stitching.

Privacy — Client-Side Conversion

Everything runs in your browser. Your HTML is read into memory, rendered in a sandboxed iframe, and written as a PDF by the open-source html2pdf library. Nothing is transmitted. The only external resources loaded are the libraries themselves from a CDN.

HTML to PDF Questions

Is my data safe?

Yes. All conversion happens locally in your browser. Your HTML is never uploaded to any server. You can disconnect from the internet after the page loads and the tool will continue to work for HTML that does not reference external resources.

What HTML features are supported?

The converter supports the same HTML and CSS your browser supports. Headings, paragraphs, lists, tables, images, inline styles, and layout modes like Flexbox and Grid all render. External resources depend on CORS, and JavaScript is not executed.

Will external CSS and images load?

It depends on the source. Same-origin resources and cross-origin resources with CORS headers load successfully. Resources without CORS headers are blocked by the browser. The safest approach is to inline CSS in a <style> block and embed images as data URLs.

Does JavaScript run during conversion?

No. The iframe is sandboxed without script execution, which prevents arbitrary code from running. Pages that rely on JavaScript to render their content will produce a PDF containing only the static HTML. To work around this, save the fully rendered page from your browser and upload that.

Can I convert a website URL directly?

The URL option is available, but it is often blocked by CORS policies — the target server may refuse to let a browser fetch its content from a different origin. For reliable results, save the page to your machine and upload the HTML file, or paste the HTML directly.

Does @media print work?

Yes. @media print rules in your CSS are respected during conversion. This is the recommended way to control exactly how the document looks on paper — hide navigation, expand link URLs, or force page breaks.

How do I force a page break?

Use CSS on the element that should start a new page: page-break-before: always or page-break-after: always. To prevent an element from being split across pages, use page-break-inside: avoid.

Will the text in the PDF be selectable?

No. The PDF pages are rasterised images, so text cannot be selected or searched. This is inherent to the rasterisation approach used by html2pdf. If you need selectable text, use a PDF library that writes real text runs, or export from a word processor.

Are links preserved in the PDF?

Links render as styled text (usually blue and underlined) but are not clickable in the PDF. The URL is visible as text but not as an interactive link. If you need clickable links, use a PDF library that supports link annotations.

What page sizes are available?

A4, Letter, Legal, A3, and A5. Each can be used in portrait or landscape orientation. Margins range from none to 20 mm. A3 is useful for wide tables and posters. A5 is useful for booklets.

Why is my PDF file so large?

Because the PDF is built from rasterised page images. Each page is rendered at high resolution and compressed as JPEG. A 10-page document at Maximum quality can be several megabytes. Choose Standard quality to reduce the file size.

Can I convert multiple HTML files at once?

Not in a single batch. The converter processes one HTML document at a time. To combine several HTML documents into one PDF, convert each one and then use the Merge PDF tool to combine the results.
