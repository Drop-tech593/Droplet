How Vector to Raster Conversion Works

SVG and PNG are fundamentally different kinds of image. SVG is vector: it describes shapes mathematically — a circle is stored as "centre point and radius", a line as "start and end coordinates". PNG is raster: it describes an image as a grid of coloured pixels, each with a specific position and colour value.

Converting from vector to raster means asking the browser to render the SVG at a specific pixel size and then capturing the resulting pixels. The browser walks the SVG's shape instructions, calculates which pixels each shape covers, applies colours and strokes, and produces a bitmap. That bitmap is then encoded as PNG.

This process is one-way. Once the SVG is rasterised, the vector information — the circles, lines, curves, and text as mathematical objects — is gone. The PNG only knows about pixels. You cannot convert a PNG back to an SVG and recover the original shapes.

Resolution and Output Dimensions

The most important choice when converting SVG to PNG is the output resolution. Because the source is vector, the browser can render it at any size — small, large, or huge — and the result will be equally sharp. This is the whole point of vector graphics.

The PNG Size option controls the output dimensions:

Option Output Size Best For
Original Size The SVG's declared width and height Quick previews, when the SVG's natural size is correct
2x Twice the original dimensions Retina displays, high-DPI screens
3x Three times the original dimensions Printing, very high-DPI displays
Fit Width: 800px Scaled so the width is 800 pixels Web assets, thumbnails
Fit Width: 1920px Scaled so the width is 1920 pixels HD screens, hero images
Fit Width: 2560px Scaled so the width is 2560 pixels 4K displays, large format
Custom Size Exact width and height in pixels Specific requirements, icon sets, embedded layouts

When using Fit Width or Custom Size, the aspect ratio is preserved unless you enter both a width and a height in Custom Size — in which case the SVG is stretched to exactly those dimensions.

Transparency

SVG and PNG both support an alpha channel. When the SVG has no background fill (which is the default for most SVG files), the areas outside its shapes are transparent. In the PNG output, those areas remain transparent when the Background option is set to "Transparent".

The Background option lets you override this:

  • Transparent — the alpha channel is preserved. Areas outside the SVG's shapes are see-through. This is the right choice for logos, icons, and any asset that will be placed over a coloured surface.
  • White / Black / Light Gray / Light Blue — the transparent areas are filled with the chosen solid colour before rendering.
  • Custom Color — pick any colour from the colour picker.

Note that some SVGs declare their own background as a filled rectangle (for example <rect width="100%" height="100%" fill="#ffffff"/>). If that rectangle is present, the SVG is not actually transparent, and the Background option will not change the result. To remove such a rectangle, edit the SVG before converting.

Scaling and Sharpness

Because SVG is vector, scaling it up before rasterisation produces a sharp result at the target size. The browser recalculates every shape at the new resolution rather than resampling an existing bitmap. A logo rendered at 2560 pixels wide from an SVG is genuinely 2560 pixels of detail — not an upscaled 400-pixel image.

This is the primary reason to convert SVG to PNG rather than to JPG or to another raster format from a screenshot. The converter is producing new pixels from the vector data, at whatever size you ask for.

The practical limit is memory. Rendering a very large canvas — 8000 × 8000 pixels or more — can exceed browser memory on lower-end devices. If you need extremely large output, render in sections or use a desktop vector editor.

Embedded Fonts in SVG

SVG files often contain text elements. The text is rendered using a font, and the font may be:

  • Referenced by name — for example font-family="Arial". The browser uses the named font if it is installed on the system, and falls back to a similar font if it is not.
  • Referenced by a web font link — the SVG includes an @font-face rule pointing to a font file on a CDN. Whether it loads depends on CORS and network access.
  • Embedded as base64 data — the font is fully contained inside the SVG. This is rare because it makes the SVG much larger, but it guarantees the text renders exactly as intended.

The practical effect: if the SVG references a font that is not installed on your system and is not embedded, the text will render in a fallback font. The output PNG will show the text in that fallback font, which may shift letter widths and change the overall layout slightly. This is a browser-level behaviour, not something the converter controls.

If the SVG is critical and uses a non-standard font, the safest approach is to convert the text to paths in a vector editor before exporting the SVG. Once the text is paths, it renders identically everywhere.

Unsupported SVG Features

The converter relies on the browser's SVG renderer. Most features are supported, but some are not:

  • External resources — an SVG that references an external image via <image href="https://..."> may fail if the resource is blocked by CORS or is not reachable. Inline images (data URLs) always work.
  • External stylesheets — an SVG that links to a CSS file via <link rel="stylesheet"> may not load the stylesheet, resulting in unstyled output.
  • Scripts inside the SVG — <script> tags are not executed. The SVG is treated as a static image.
  • Animations — SMIL animations and CSS animations inside the SVG are not captured. The browser renders the initial state, which is what the PNG will contain.
  • Filters and blend modes — most SVG filters (Gaussian blur, drop shadow, colour matrix) are supported, but very complex filter chains may render differently in different browsers.
  • Foreign objects — <foreignObject> elements, which embed HTML inside an SVG, may render inconsistently across browsers.

If your SVG relies on one of these features, the safest approach is to open the SVG in a browser, take a screenshot of how it renders, and use that as a reference when reviewing the converted PNG.

What Is Preserved and What Is Not

Preserved:

  • All shapes and paths, rendered at the chosen resolution.
  • Colours and strokes.
  • The alpha channel, when the Background option is Transparent.
  • Text, rendered in the font the browser selects.

Not preserved:

  • Vector information — the PNG is a fixed-resolution bitmap.
  • Any metadata attached to the SVG file.
  • Animation timing, if the SVG contained animations.
  • Interactivity — clickable SVG links are not preserved in the PNG.

SVG to PNG Questions

Is my data safe?

Yes. All conversion happens locally in your browser. Your SVG files are never uploaded to any server. You can disconnect from the internet after the page loads and the tool will continue to work for SVGs that do not reference remote resources.

Why convert SVG to PNG?

PNG is universally supported and displays identically on every device. Some older platforms, email clients, and design tools cannot open SVG directly. Converting to PNG produces a fixed-resolution image that works everywhere.

Will I lose quality?

The PNG is rendered from the SVG's vector data at the resolution you choose, so the output is as sharp as the target size allows. There is no "quality loss" in the JPEG sense, but the vector information is gone — the PNG cannot be scaled up again without becoming pixelated.

What resolution should I choose?

For web use at normal size, Fit Width 800px is usually enough. For retina displays, use 2x or Fit Width 1920px. For print, use 3x or Fit Width 2560px, or a custom size matching your print DPI. Choose Original Size when the SVG's declared dimensions are already correct.

Is transparency preserved?

Yes, when the Background option is set to Transparent. Areas outside the SVG's shapes stay transparent in the PNG. If the SVG itself contains a full-page background rectangle, the output will not be transparent regardless of the setting.

Will my text render correctly?

Text is rendered in whatever font the browser selects. If the SVG references a font that is installed on your system or embedded in the SVG, the text renders exactly. If not, a fallback font is used, which may shift the layout. Convert text to paths in a vector editor for guaranteed fidelity.

Are external images in the SVG loaded?

Only if CORS allows it and the resource is reachable. Inline images (data URLs) always work. External URLs may fail. For the most reliable result, inline all resources into the SVG before converting.

Are animations and scripts in the SVG preserved?

No. The SVG is treated as a static image. Animations and scripts are not executed, and the browser renders only the initial state of the SVG. The PNG captures that single frame.

Can I convert multiple SVG files at once?

Yes. Drag and drop several SVG files or select them all in the file picker. Each file is converted with the same options. You can then download everything as a ZIP archive or download them individually.

Can I set a custom background colour?

Yes. Choose "Custom Color" in the Background dropdown and pick any colour. The transparent areas of the SVG will be filled with that colour in the PNG.

Can I use this for icons and favicons?

Yes. Choose Custom Size and enter the exact pixel dimensions you need — for example 32 × 32 for a favicon. Set Background to Transparent so the icon blends with any surface.

What is the maximum file size?

About 10 MB per SVG. This is generous because SVGs are text files and rarely exceed a few hundred kilobytes. If your SVG is larger, it likely contains embedded raster images; consider flattening it first.
