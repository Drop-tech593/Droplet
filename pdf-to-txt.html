How Text Extraction Works

A PDF can contain text in two very different ways. Most PDFs created from Word, Google Docs, or a publishing tool store each character as a positioned glyph with an embedded font — this is called a text layer. Scanned PDFs, on the other hand, are just pictures of pages with no text layer at all.

This tool handles both cases. For each page, it first tries to read the text layer using PDF.js. If the page has enough readable text, that text is used directly. If the page has little or no text layer — which is what happens on scanned pages — the tool automatically falls back to OCR (Optical Character Recognition) using Tesseract.js, which reads the page image and guesses the characters.

The decision is made per page, not per document. A PDF that mixes scanned pages with text-based pages will use the text layer where it exists and OCR where it doesn't.

Reading Order

PDFs do not store text in reading order. They store it in the order the original authoring tool drew each character, which can be back-to-front, column by column, or completely jumbled. PDF.js reads items in their internal order and returns them that way.

For simple, single-column documents — letters, articles, reports — the internal order is usually close to reading order, so the extracted text reads naturally. For multi-column layouts, text boxes, sidebars, or pages with overlapping elements, the output can be scrambled. Column 1 and column 2 may interleave, or a caption may appear in the middle of a paragraph.

This is a limitation of the PDF format, not of the tool. Fixing it requires layout analysis that detects columns and reconstructs reading order — a much harder problem.

Encoding and Character Support

PDF.js decodes the text layer and returns JavaScript strings, which are UTF-16 internally. The output TXT file is written as UTF-8. This means accented Latin letters (é, ñ, ü), Greek, Cyrillic, and most CJK characters come through correctly if the PDF's text layer stores them properly.

Problems arise when the PDF uses a font with a non-standard encoding, or when the text layer stores character codes that don't map cleanly to Unicode. In those cases you may see garbled characters, question marks, or missing letters. This is uncommon in modern PDFs but does happen with older or poorly-generated files.

Line Breaks and Whitespace

The extractor joins text items with a single space and collapses runs of multiple spaces into one. It preserves paragraph breaks where the PDF's text layer indicates a new line or block, but it does not attempt to reconstruct the visual line breaks you see on the page.

In practice, this means:

  • Wrapped lines within a paragraph become one continuous line in the output.
  • Hard line breaks (like the ones after a heading) are usually preserved.
  • Blank lines between paragraphs are often preserved but not guaranteed.
  • Indentation and leading whitespace are stripped.

If you need exact visual line breaks, use the PDF to Markdown converter, which analyses the position of each text item and reconstructs lines and paragraphs more carefully.

Scanned PDFs and OCR

When a page has no usable text layer, the tool renders the page as a high-resolution image (3× scale) and runs Tesseract.js on it. Tesseract is a well-known open-source OCR engine that runs entirely in the browser.

OCR is slower than reading a text layer — typically a few seconds per page — and the accuracy depends on the quality of the scan:

  • Clean, high-contrast scans (300 dpi or higher, straight pages, dark text on white paper) usually come through with good accuracy.
  • Skewed, blurry, or low-contrast scans produce more errors, especially on numbers, punctuation, and similar-looking letters (l vs 1, O vs 0, rn vs m).
  • Handwriting is generally not recognised well. Tesseract is trained on printed text.
  • Tables and multi-column layouts often lose their structure — cells may be read in the wrong order or merged into one line.

OCR runs in English by default. Other languages will produce poor results unless the language model is loaded, which this tool does not currently do.

What Does Not Survive Extraction

  • Formatting — bold, italic, font size, colour, and alignment are all lost. The output is plain text.
  • Images — pictures embedded in the PDF are not extracted. If a page has a diagram with captions, the captions come through but the diagram does not.
  • Tables — table structure is lost. Rows and columns become a stream of text. The PDF to Markdown converter does a better job with simple tables.
  • Hyperlinks — URLs may appear as text if they were visible in the PDF, but they are not clickable links in the output.
  • Headers and footers — repeating page headers and footers appear once per page in the output, which can be noisy. You may want to remove them manually.
  • Footnotes — footnote text usually ends up at the end of each page's extracted text rather than linked to the reference.

Practical Uses

Feeding text into an AI tool: Extract the text, then paste it into a chatbot or summarizer. TXT is the cleanest format for that.

Searching a document archive: Extract text from a batch of PDFs and grep across the TXT files to find which documents mention a keyword.

Reusing content in a new document: Copy the extracted text, paste it into your word processor, and reformat it as needed.

Data processing and analysis: TXT is easy to parse with scripts. Extract, then run your own analysis.

Privacy — Client-Side Extraction

PDF parsing uses PDF.js and OCR uses Tesseract.js. Both run entirely in your browser. Your PDF is read into memory and never transmitted. The only external resources loaded are the libraries themselves from a CDN.

PDF to TXT Questions

How does the tool decide between text extraction and OCR?

For each page, it reads the text layer first. If the page has at least about 80 characters, 40 letters, and 10 words, that text is considered usable and is used directly. Otherwise the page is treated as scanned and OCR is run on it.

Why is my extracted text in the wrong order?

PDFs store text in drawing order, not reading order. Multi-column layouts, sidebars, and text boxes often come out scrambled. This is a limitation of the PDF format itself. For better ordering on structured documents, use the PDF to Markdown converter.

Will formatting like bold and italics be preserved?

No. TXT is plain text. Bold, italic, font size, colour, and alignment are all lost. If you need formatting, use the PDF to DOCX converter instead.

Are images and tables included?

No. Images are not extracted. Tables lose their structure and become a stream of text. For tables with real structure, use the PDF to Markdown converter, which can produce Markdown tables from simple, evenly-spaced tables.

How accurate is the OCR for scanned PDFs?

It depends on scan quality. Clean, high-contrast, straight scans usually give good results. Skewed, blurry, or low-resolution scans produce more errors, especially on numbers and punctuation. Handwriting is generally not recognised well.

Does OCR support languages other than English?

No. The tool loads only the English language model for Tesseract. Other languages will produce poor results. If you need multi-language OCR, use a dedicated OCR service.

Why does the extraction take so long on some PDFs?

OCR is the slow part. Reading a text layer is nearly instant, but rendering a page to an image and running Tesseract on it takes a few seconds per page. A 50-page scanned PDF can take a few minutes.

Can I extract text from a password-protected PDF?

No. The tool can only read PDFs that open without a password. Remove the protection first using a dedicated PDF tool, then extract the text here.

Are headers and footers included in the output?

Yes, they appear once per page in the extracted text because the tool reads every line on every page. You may want to remove them manually after extraction, especially on long documents.

What is the maximum PDF size?

About 100 MB. The practical limit depends on your device's memory, since everything runs in the browser. Very long documents or those with many scanned pages may take a long time to process.

Is my PDF uploaded to a server?

No. All parsing and OCR happen locally in your browser using PDF.js and Tesseract.js. Your file never leaves your device. You can disconnect from the internet after the page loads and the tool will continue to work.

Can I edit the TXT file after downloading?

Yes. The output is a plain .txt file. You can open it in Notepad, TextEdit, VS Code, or any text editor, and edit it freely.
