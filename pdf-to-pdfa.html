What This Tool Actually Produces

This converter reads your PDF, renders each page as a high-resolution image at the quality setting you choose, and writes those images into a new PDF. The result is a flat, self-contained PDF: every page is a single full-page image, and the file carries no external fonts, no scripts, no forms, no encryption, and no links to outside resources.

That makes it stable. Any PDF reader on any platform will display it identically, because there is nothing to interpret beyond embedded JPEG images. It will still look the same in twenty years, as long as the reader can display a JPEG.

What it is not is standards-compliant PDF/A. The sections below explain the difference honestly.

What PDF/A Actually Requires

PDF/A is an ISO standard (ISO 19005) with multiple parts. Every part imposes specific requirements. A PDF that claims to be PDF/A-1b, PDF/A-2b, or PDF/A-3b must satisfy all of the following:

  • XMP metadata in the document catalog declaring the PDF/A part and conformance level (for example pdfaid:part = 2 and pdfaid:conformance = B).
  • Embedded fonts for every glyph used in the document, subsetted, with correct licencing flags. No font may be referenced by name only.
  • Device-independent colour. Every colour space in the file must be CalRGB, CalGray, Lab, ICCBased, or an Indexed / Separation variant built on one of those. DeviceRGB and DeviceCMYK are not allowed.
  • A PDF/A output intent: an ICC profile describing the intended rendering, referenced from the document catalog.
  • No encryption, no JavaScript, no audio or video, no external references.
  • For PDF/A-2 and PDF/A-3: additional conformance around transparency, JPEG 2000, and (for PDF/A-3) embedded files.

Producing a file that passes all of these checks requires either a server-side tool like Ghostscript, or a JavaScript library that writes PDF/A structures directly and embeds a valid ICC profile and XMP packet. The library used by this page, html2pdf, does neither. It wraps rasterised pages into a generic PDF container.

What Droplet Does Not Do

  • It does not embed fonts. Fonts are not used at all. Every page is a JPEG image, and images have no font dependency.
  • It does not write PDF/A XMP metadata. The output has no pdfaid:part or pdfaid:conformance declaration.
  • It does not declare an output intent. There is no ICC profile in the document catalog.
  • It does not guarantee device-independent colour. JPEG colour is stored as YCbCr derived from sRGB, which is device-dependent under the PDF/A rules.
  • It does not preserve selectable text. Text becomes part of the page image and is no longer searchable or selectable.
  • It does not preserve metadata, bookmarks, or links. All of that is lost when the page is rendered to an image.

Why It Still Might Be Useful

Despite not being PDF/A, the output has real value in several situations:

  • Locking the visual appearance of a document. If a PDF uses custom fonts that may not be available on the recipient's machine, flattening to images guarantees the document looks identical everywhere.
  • Removing metadata before sharing. EXIF, XMP, bookmarks, annotations, and embedded files are all stripped. The output contains only page images.
  • Creating a self-contained copy. The output has no external dependencies. It does not reference remote images, web fonts, or linked files.
  • Reducing complexity. A PDF that used interactive forms, JavaScript, or embedded video becomes a simple image-based document.

How to Produce Real PDF/A

If you need a genuinely PDF/A-compliant file, you have to use a tool that implements the standard. Reliable options include:

  • Ghostscript with the pdfa or PDFA_def.ps output device. Command line, produces true PDF/A.
  • Adobe Acrobat Pro with the Preflight tool. Choose "Convert to PDF/A-1b" or "PDF/A-2b".
  • LibreOffice Draw with the "Export as PDF" dialog, choosing PDF/A-2b in the PDF/A options.
  • veraPDF to validate a candidate PDF/A file. If it fails validation, it is not PDF/A regardless of its name.

For documents that must be archived under a legal or regulatory requirement, use a validated PDF/A tool and check the output against veraPDF before submitting it. Do not rely on a browser-only converter for a compliance-critical workflow.

Practical Uses of the Archival PDF

Locking a signed contract to its exact appearance: Convert the signed PDF into a flat archival copy so no font substitution or layout shift can occur on the recipient's machine.

Producing a redacted copy: Convert to images and the underlying text layer is removed entirely. Useful when the text is not needed but the visual appearance is.

Reducing a complex PDF for email: Choose Grayscale and Standard quality to produce a small file that preserves the visual content but drops all interactive and metadata overhead.

Creating a stable preview copy: When sending a design mockup or document preview to someone who may not have the original fonts, a flat archival copy guarantees the preview matches what you see.

Archival PDF Questions

Is this output actually PDF/A compliant?

No. The output is a flat, self-contained PDF where each page is an image, but it does not carry the XMP metadata, embedded fonts, output intent, or device-independent colour required by the PDF/A standard. It will not pass a veraPDF or Adobe Preflight PDF/A validation. For real PDF/A, use Ghostscript, Acrobat Pro, or another validated tool.

Why not call it PDF/A if it looks like a PDF/A file?

Because "PDF/A" is a well-defined technical standard, not a general description. A file that fails validation is not PDF/A, even if it looks like one. Claiming otherwise would mislead users who need compliance for legal, regulatory, or archival purposes.

What is the output good for, then?

It is useful when you need a stable, self-contained copy of a PDF that looks the same on every device. It strips metadata, links, forms, JavaScript, and embedded files, and replaces them with page images. It is a good choice for reducing complexity, locking the visual appearance, or producing a redacted copy.

What does "flat PDF" mean?

A flat PDF has no interactive elements. There are no form fields, no links, no annotations, no scripts. Every page is essentially an image. This makes the file predictable across readers but removes the ability to select or search the text.

Are fonts embedded in the output?

Fonts are not used. Every page is rendered to an image before the PDF is written, so there is no font dependency at all. The visual appearance of the original fonts is preserved as pixels, but the fonts themselves are not present in the output.

Is the text in the output selectable?

No. Once a page is rasterised, the text becomes part of the image. You cannot select, copy, or search it. If you need selectable text, keep the original PDF or use the PDF to TXT converter.

What metadata is preserved?

None of the original metadata is preserved. EXIF, XMP, document title, author, bookmarks, annotations, and embedded files are all discarded. The output contains only the page images and basic dimensions.

Can I choose between colour and grayscale?

Yes. RGB preserves the original colours. Grayscale converts each page to shades of grey and reduces file size by roughly 30–50%. Use Grayscale for text-heavy documents where colour adds no information.

What quality setting should I use?

High (0.85) is the default and works for most documents. Use Standard (0.7) if file size matters more than detail. Use Maximum (0.95) if the document will be printed or contains fine detail such as technical drawings.

Why is the output larger than the original?

Because each page is stored as a full-page JPEG image. Vector text and line art take very little space in a normal PDF, but the equivalent raster image is much larger. This is the trade-off for a flat, self-contained file.

Can I convert a password-protected PDF?

No. Remove the password first with a dedicated tool, then convert the unlocked file here.

How do I actually produce real PDF/A?

Use a validated tool: Ghostscript with the PDF/A device, Adobe Acrobat Pro's Preflight tool, or LibreOffice's PDF/A export. Always verify the output with veraPDF, which is a free PDF/A validator, before submitting it to a compliance-critical workflow.
