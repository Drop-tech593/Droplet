How AVIF to PNG Conversion Works

The converter hands your AVIF file to the browser's built-in AVIF decoder, reads the decoded pixels, draws them onto an HTML canvas, and then re-encodes the canvas in the output format you chose. This is a decode-and-re-encode pipeline, not a simple file rename.

Everything runs locally. Your file is never uploaded, and the output is written straight to your device through a Blob URL. The only network request made is to load the libraries that power the page.

Transparency

AVIF supports an alpha channel, and so does PNG. When the input AVIF has transparent areas, the alpha channel is preserved in the output PNG. A logo with a transparent background remains transparent after conversion.

This behaviour is inherent to the canvas pipeline — the browser keeps the alpha channel when drawing the image, and PNG has a native alpha channel to write it out. No special option is required.

If your source AVIF has a solid background (no transparency), the output PNG will also be fully opaque. There is no way to introduce transparency from a fully opaque source.

Bit Depth and HDR Limitations

AVIF is capable of storing 10-bit and 12-bit colour, and it can carry HDR metadata for high dynamic range displays. This is one of its key advantages over JPG and WebP.

However, the browser's canvas API works in 8-bit sRGB. When the AVIF decoder outputs a 10-bit or 12-bit image, the canvas flattens it to 8 bits per channel before the conversion can proceed. This means:

  • HDR content is tone-mapped to standard dynamic range. Highlights that were above 1.0 in HDR will appear clipped at the maximum sRGB value.
  • 10-bit gradients are reduced to 8-bit precision. Banding that was not visible in the original may appear in smooth gradients after conversion.
  • Wide-gamut colours are clipped to the sRGB gamut. Rec. 2020 and Display P3 primaries that fall outside sRGB will be mapped to the nearest in-gamut colour, usually with some loss of saturation.

If you need to preserve 10-bit precision or HDR metadata, PNG is not the right output format. Use a tool that supports 16-bit PNG output and HDR-aware colour management.

Colour Profiles and Colour Management

AVIF files can carry an embedded ICC profile or declare a colour space in their container metadata. Common colour spaces for AVIF include sRGB, Display P3, and Rec. 2020.

The browser's decoder applies the file's declared colour space to interpret the pixel values, then the canvas draws them in its working space, which is sRGB. As a result:

  • sRGB AVIF files pass through unchanged. This is the most common case, since most AVIF content is authored in sRGB.
  • Display P3 AVIF files are converted to sRGB. Colours inside the sRGB gamut look the same; colours outside are clipped toward the boundary.
  • Rec. 2020 AVIF files are converted to sRGB with visible saturation loss for highly saturated colours.

The output PNG does not carry any embedded ICC profile. It is treated as sRGB by default by every consumer of the file. This is the safest choice because sRGB is universally understood, but it does mean that any wide-gamut information in the source is lost.

Browser Decoding — What Depends on Your Browser

This tool does not implement its own AVIF decoder. It relies entirely on the browser's built-in decoder. That has three practical consequences:

  • Modern browsers decode AVIF natively. Chrome 85+, Firefox 92+, Safari 16.4+, and Edge 121+ all include AVIF decoders. On these browsers, the tool works directly.
  • Older browsers cannot decode AVIF. If the browser does not include an AVIF decoder, the file will fail to load and the conversion will not proceed. You will see an error message in the results panel.
  • Decoding behaviour varies slightly between browsers. Different browser versions handle HDR tone mapping, gamut mapping, and edge cases in the AVIF spec differently. The same file may produce slightly different pixel values in Chrome vs Safari.

This is why the tool is honest about its dependencies. It is not a standalone decoder; it is a client-side wrapper around the browser's decoder plus a re-encoder. For most sRGB 8-bit AVIF content, the result is essentially identical to the source. For HDR or wide-gamut content, the browser's tone mapping determines the output.

Metadata — What Gets Stripped and Why

AVIF files can carry a substantial amount of metadata: EXIF (camera make, model, GPS coordinates, capture date), XMP (editing history, keywords, ratings), and container metadata (colour profile, HDR signalling, alpha premultiplied flag).

During conversion, all of this metadata is discarded. Here is why:

  • The canvas has no metadata API. When the browser draws an image onto a canvas, only pixels are transferred. Metadata attached to the source image does not survive.
  • The PNG encoder writes only pixel data plus basic dimensions. The Blob produced by canvas.toBlob() contains no EXIF or XMP chunks.
  • Privacy is a benefit. Stripping GPS coordinates and camera information makes it safer to share converted images publicly.

If you need to preserve metadata, you would need a dedicated tool that reads the AVIF container, extracts metadata, and re-embeds it in the PNG. That is outside the scope of a browser-only converter.

Resolution and Image Dimensions

The output image uses the source dimensions by default. A 1920 × 1080 AVIF becomes a 1920 × 1080 PNG. Aspect ratio is always preserved.

The Image Size option caps the longest edge at 3840, 1920, 1280, or 800 pixels. When downscaling is applied, the browser uses high-quality interpolation. Original Size keeps the native resolution with no resampling.

What Is Preserved and What Is Not

Preserved:

  • Pixel values in 8-bit sRGB (subject to the tone-mapping and gamut-mapping described above).
  • The alpha channel, when the source has transparency.
  • Image dimensions and aspect ratio (unless downscaled).

Not preserved:

  • EXIF, XMP, and container metadata.
  • HDR metadata and 10-bit / 12-bit precision.
  • Embedded ICC colour profiles.
  • Any animation (AVIF supports image sequences; only the first frame is converted).

AVIF to PNG Questions

Is my data safe?

Yes. All conversion happens locally in your browser. Your AVIF files are never uploaded to any server. You can disconnect from the internet after the page loads and the tool will continue to work for files that are already loaded.

Why convert AVIF to PNG?

AVIF is a modern format with excellent compression, but it is not yet supported by all devices, applications, and platforms. PNG is universally supported and offers lossless quality, making it ideal for sharing, editing, and printing.

Will I lose image quality?

The pixel data is preserved as closely as the browser's decoder allows. For 8-bit sRGB AVIF content, the PNG is essentially pixel-identical. For 10-bit, HDR, or wide-gamut AVIF content, the browser tone-maps and gamut-maps to 8-bit sRGB, which does involve some loss of detail and colour.

Is transparency preserved?

Yes. AVIF and PNG both support an alpha channel, and the canvas pipeline preserves it. Transparent areas of the source AVIF stay transparent in the output PNG.

What about 10-bit and HDR AVIF files?

The browser's canvas works in 8-bit sRGB. When the AVIF decoder outputs 10-bit or HDR content, the canvas flattens it to 8 bits and tone-maps HDR values into the standard sRGB range. Highlights that were above 1.0 in HDR will be clipped. If you need to preserve HDR, use a tool that supports 16-bit PNG output and HDR colour management.

What happens to wide-gamut colour spaces?

Display P3 and Rec. 2020 AVIF files are converted to sRGB. Colours inside the sRGB gamut look the same; colours outside are clipped toward the sRGB boundary. The output PNG carries no ICC profile and is treated as sRGB.

Are metadata like GPS and camera info preserved?

No. EXIF, XMP, and container metadata are all stripped during conversion. The canvas API works with pixels only, and the PNG encoder writes no metadata chunks. This is good for privacy but means descriptive metadata is lost.

Why does my browser refuse to load the AVIF?

The tool relies on the browser's built-in AVIF decoder. Chrome 85+, Firefox 92+, Safari 16.4+, and Edge 121+ include AVIF support. Older browsers do not, and the file will fail to load. Update your browser or use a different one.

Can I convert animated AVIF files?

The first frame of an animated AVIF is converted. Subsequent frames and the animation timing are not preserved, because the canvas pipeline captures only the frame that the browser renders on load. For animation conversion, use a dedicated animated-image tool.

Can I resize the image during conversion?

Yes. Choose an Image Size option to cap the longest edge at 3840, 1920, 1280, or 800 pixels. Original Size keeps the native resolution. Aspect ratio is always preserved.

What other output formats are available?

In addition to PNG, the tool can output JPG and WebP. JPG produces smaller files but does not support transparency. WebP supports transparency and produces smaller files than PNG, but is less universally supported than PNG.

Can I convert multiple files at once?

Yes. Drag and drop several AVIF files or select them all in the file picker. Each file is converted independently. You can then download everything as a ZIP archive or download them individually.
